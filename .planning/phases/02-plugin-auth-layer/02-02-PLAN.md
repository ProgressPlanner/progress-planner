<feature>
  <name>Remote API auth layer verification</name>
  <files>tests/phpunit/test-class-rest-remote-base.php, classes/rest/class-remote-base.php</files>
  <behavior>
    Test cases for Bearer token extraction:
    - Valid `Authorization: Bearer <token>` header → returns token string
    - Missing Authorization header → returns WP_Error with `invalid_token` code, 401 status
    - Authorization header without "Bearer " prefix → returns WP_Error with `invalid_token` code, 401 status
    - Empty Bearer value (`Authorization: Bearer `) → behavior test

    Test cases for HMAC signature verification:
    - Valid signature + valid timestamp → returns true
    - Missing x_pp_server_signature header → returns WP_Error with `invalid_token` code, 401 status
    - Missing x_pp_server_timestamp header → returns WP_Error with `invalid_token` code, 401 status
    - Invalid/tampered signature → returns WP_Error with `invalid_token` code, 401 status
    - Expired timestamp (>300 seconds ago) → returns WP_Error with `invalid_token` code, 401 status
    - Future timestamp (>300 seconds ahead) → returns WP_Error with `invalid_token` code, 401 status
    - Timestamp exactly at boundary (300 seconds) → accepted (within tolerance)

    Test cases for full check_permission flow:
    - Valid Bearer token + valid HMAC → returns true
    - Invalid Bearer token → returns WP_Error before HMAC check
    - Valid Bearer token + invalid HMAC → returns WP_Error
  </behavior>
  <implementation>
    Create a concrete test subclass of Remote_Base (since it's abstract) that exposes auth methods for testing. Follow the existing test patterns from test-class-rest-base.php.

    Use `WP_REST_Request` mock objects with headers set via `set_header()`.
    Set up test tokens via `update_option('progress_planner_test_token', ...)`.
    Generate valid HMAC signatures using `hash_hmac('sha256', body . timestamp, token)`.
  </implementation>
</feature>
